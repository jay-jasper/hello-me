# 「断夜 / NIGHT//CUT」独立主题设计

- 日期：2026-07-13
- 状态：设计已确认，等待规格审阅
- 目标路由：`/nightfall/`
- 现有主题路由：`/`

## 1. 概述

「断夜 / NIGHT//CUT」是个人网站的第二套完整主题。它提炼酸性视觉、利落动作、物理冲击和强色彩层次，以“一夜一战”为叙事，把同一份个人资料与人生记忆重新编排为连续战线。

新主题不是现有深海主题的换肤。两套主题拥有独立的 HTML 入口、DOM 结构、CSS、WebGL 场景、动画编排、音频和生命周期，只共享同一份个人内容与中立主题路由信息。用户可以在两个主题间双向切换，并停留在同一内容章节。

视觉设计不得复制参考作品的角色、标志、具体招式、画面或音乐；只采用抽象的速度、切割、色差、定格和空间折射语言。

## 2. 目标与成功标准

### 2.1 首要目标

访客进入 `/nightfall/` 后，页面应在 2.8 秒内完成“蓄势—锁定”并等待首次输入；访客产生首次输入后的 7.2 秒内，应完成“瞬斩—战线显形”并展示真实内容，使整条标准交互路径控制在 10 秒内。

### 2.2 次要目标

- 同一份个人内容在两套主题中保持一致，不需要重复维护。
- 滚动自然推进战斗，点击或滑动可以主动出招，但不构成内容访问门槛。
- 桌面与移动端保持相同构图、颜色、招式与节奏；渲染精度可自适应。
- 正文出现后强动效迅速退场，保证阅读与键盘操作。
- 用户可随时切换主题，并定位到相同内容章节。

### 2.3 非目标

- 不制作游戏式伤害、生命值、胜负或角色养成系统。
- 不让访客依靠手势成功与否才能解锁内容。
- 不在一个页面内同时加载或热切换两套 WebGL 运行时。
- 不复用现有深海主题的场景、样式、组件、颜色变量或海洋叙事。
- 不使用参考作品的受版权保护素材。

## 3. 已确认的产品决定

| 决定项 | 结论 |
| --- | --- |
| 页面形态 | 新主题使用独立 URL `/nightfall/` |
| 内容 | 与现有主题读取完全相同的个人资料和记忆内容 |
| 主题关系 | 视觉与运行时独立，允许双向切换 |
| 视觉母题 | 瞬斩残响 |
| 色谱 | 近黑背景、电紫空间残影、冰青锋线、白色命中闪光 |
| 动效节奏 | 平时冷静蓄势，章节与交互时爆发，随后迅速归静 |
| 叙事 | 一夜一战，人生阶段是连续突破的战线 |
| 内容版式 | 左右交错战术面 |
| 声音 | 默认静音，用户主动开启后才加载与播放 |
| 设备 | 跨端保持相同观感与编排，内部自适应渲染质量 |
| 控制 | 滚动推进；点击、拖拽或滑动提供额外出招反馈 |
| 首要成功标准 | 前 10 秒形成强烈且可记忆的视觉冲击 |

## 4. 视觉与体验设计

### 4.1 品牌气质

核心词为：锋利、克制、决绝、迅疾。

页面大部分时间保持近黑与低噪声，只在关键输入和章节切换时释放高亮能量。视觉冲击来自明暗反差、短时定格和方向明确的切割，而不是持续堆叠粒子或震屏。

基础色彩：

| 语义 | 建议色值 | 用途 |
| --- | --- | --- |
| Night | `#07060B` | 页面与 WebGL 基底 |
| Tactical Surface | `#0E0C17` | 战术面板 |
| Ice Cyan | `#67EFFF` | 锁定线、锋线、主要交互反馈 |
| Electric Violet | `#8C49FF` | 空间残影、折射和次级能量 |
| Impact White | `#F4F2FF` | 极短命中核心与主文字 |
| Muted Ink | `#A7A3B5` | 次级文字与非活动 HUD |

禁止沿用深海主题的蓝黑水体渐变、琥珀诱饵光、海雪、深度暗角或生物荧光层级。

### 4.2 前 10 秒签名开场

以下时间以访客在 2.8 秒锁定完成后立即产生首次输入的标准路径计。若访客尚未输入，页面停留在低活动的 `armed` 状态，不自动斩击、不循环闪光；滚动、点击、滑动、Enter 或 Space 均可继续。

1. **0.0–1.2 秒：黑场蓄势**  
   近黑画面只显示一道微弱冰青水平线、静音状态和极轻噪声。没有自动播放声音。
2. **1.2–2.8 秒：锁定身份**  
   电紫空间残影收束为 `LEE`，圆形锁定线根据指针或触摸位置产生小幅视差。
3. **2.8–4.2 秒：瞬斩破幕**  
   第一个滚动、点击或滑动输入触发白刃斜切、冰青锋线、电紫色差残影、80 毫秒命中定格和受限镜头冲击。
4. **4.2–10.0 秒：战线显形**  
   破幕碎片重组为左右交错战术面：左侧显示“此刻”，右侧预告第一段记忆，底部显示 `SCROLL TO ENGAGE`。

从带有有效内容片段的主题切换 URL 进入时跳过完整开场，改用不超过 400 毫秒的轻量锁定动画，直接定位目标章节。

### 4.3 整场路线

1. **断夜开场**：建立身份、声音状态与输入规则。
2. **此刻战线**：展示 `now` 内容与社交链接，确保核心名片无需完成整场体验即可获得。
3. **记忆战线**：按共享数据中的既有顺序展示全部记忆；每个节点先锁定年份和标题，命中后展开完整正文。
4. **最终命中**：最后一段记忆使用规模最大的多层残影，但不引入新规则。
5. **破晓收束**：背景从近黑过渡为冷灰白，战术线汇成个人签名；提供返回顶部、再次浏览和社交链接，不自动跳转旧主题。

### 4.4 左右交错战术面

- 内容节点在左右两侧交替出现，避免卡片网格。
- 每个面板包含战线编号、年份、标题和故事正文。
- 未进入阅读状态时只显示短信息；命中后正文展开并获得完整对比度。
- 阅读状态下暂停震屏、强折射、密集粒子和持续残影。
- 固定 HUD 只包含主题名/声音开关、当前战线编号和底部进度线。
- 不出现深度计、“浮出水面”、海洋物种或旧主题 HUD 语言。

### 4.5 交互状态机

每个章节只允许以下状态：

1. `idle`：当前章节尚未接近，渲染器保持低活动状态。
2. `armed`：章节进入预热区，锁定线与低强度残影出现。
3. `impact`：跨越阈值或主动出招时播放一次可取消的命中编排。
4. `reading`：正文进入主要阅读区，强动效停止，DOM 获得焦点与完整对比度。
5. `leaving`：离开阅读区，收起面板并预热下一章节。

快速反向滚动时，当前编排必须可取消并由目标章节状态接管，禁止排队播放过期动画。

滚动决定章节进度，不决定内容权限。点击、拖拽和滑动只产生额外刀痕与残影反馈；键盘和辅助技术用户无需模拟挥刀。

## 5. 主题切换与 URL 契约

### 5.1 路由

- 深海主题：`/`
- 断夜主题：`/nightfall/`

两个页面分别完整加载自己的入口。主题切换使用普通导航，不在当前页面动态导入另一套主题运行时。

### 5.2 稳定内容 ID

共享内容中的每个可定位节点必须拥有唯一、稳定、与主题无关的 `id`。ID 使用小写短横线格式，一经发布不得随标题变化，例如 `first-loved-job`。

URL 片段契约：

- `#now`：此刻内容
- `#memory/<id>`：指定记忆
- `#end`：主题结尾

示例：用户在 `/#memory/first-loved-job` 点击主题切换后，导航至 `/nightfall/#memory/first-loved-job`。

### 5.3 切换行为

- 每个主题都在固定但不抢占正文注意力的位置提供明确命名的主题切换按钮。
- 有效片段进入目标主题时，直接定位同一内容并播放轻量入场。
- 无片段的正常访问播放完整主题开场。
- 片段格式错误或 ID 不存在时，安全回到目标主题顶部并清理无效片段。
- 两个主题不共享滚动像素位置、动画帧、WebGL 对象或音频状态。

## 6. 架构与模块边界

### 6.1 共享中立层

两套主题共同读取：

- 个人资料：姓名、此刻、社交链接和结尾内容。
- 记忆资料：稳定 ID、年份、类型、标题和故事正文。
- 内容类型定义与校验。
- 中立主题路由表：主题标识、显示名称和路径。

“内容一样”意味着个人内容字段来自同一份源数据，不为不同主题复制或改写。主题可以增加自己的 HUD、章节编号和过渡文案，但不得改变共享故事正文。

### 6.2 独立断夜入口

断夜主题至少拆分为以下职责单一的单元：

- **NightfallApp**：创建和销毁本主题，连接其他模块。
- **ContentAdapter**：把共享内容映射为断夜章节模型，不修改源数据。
- **BattleTimeline**：管理章节阈值、当前战线、阅读锁定和破晓状态。
- **CombatRenderer**：独立 WebGL 场景和所有 GPU 资源。
- **Choreography**：开场、锁定、命中、收束等可取消动画时间线。
- **GestureLayer**：统一滚轮、键盘、指针、拖拽和触摸输入。
- **AudioDirector**：在用户授权后加载与控制环境、拔刀和命中音轨。
- **BattleHUD**：语义化 DOM 的声音、战线、进度和主题切换控件。
- **QualityPolicy**：在不改变编排的前提下选择渲染质量。

任何断夜模块不得导入现有深海主题的 `src/main.ts`、`src/scene.ts` 或 `src/style.css`。可以继续使用项目已有的 Three.js 依赖，因为库依赖不构成主题运行时共享。

### 6.3 数据流

```text
共享个人内容
  → ContentAdapter 生成章节模型
  → BattleTimeline 计算当前章节与状态
  → DOM 渲染完整可访问内容
  → Choreography 生成短时视觉指令
  → CombatRenderer / AudioDirector 执行表现
```

WebGL 与音频层不能成为内容渲染的前置条件。即使表现层完全失败，DOM 仍应包含全部个人内容和主题导航。

### 6.4 生命周期

NightfallApp 销毁时必须：

- 取消所有动画帧和未完成编排。
- 注销滚动、指针、触摸、键盘、尺寸和可见性监听器。
- 停止并释放音频节点。
- dispose 几何体、材质、纹理、渲染目标和 WebGLRenderer。
- 清理主题专属 DOM 状态，不修改共享内容。

## 7. 渲染与特效系统

### 7.1 图层顺序

1. 近黑基础场与低频噪声。
2. 战线、锁定环和远景方向线。
3. 主刀光几何与命中核心。
4. 电紫/冰青残影和碎片。
5. 局部空间折射与受限色差。
6. DOM 内容、HUD 与焦点状态。

后处理只作用于 WebGL 层，不扭曲正文 DOM。

### 7.2 主动出招

- 点击：以按下位置为命中点生成短刀痕。
- 指针拖拽：按起止方向生成一次斩线，长度和速度只影响表现强度。
- 触摸滑动：使用与拖拽相同的方向模型。
- 无有效方向输入：仍提供短促点状命中反馈。

主动出招不改变章节、内容顺序或 URL。

### 7.3 自适应质量

所有质量档必须保持同一镜头构图、颜色、招式时序和章节状态。只允许调整：

- 渲染 DPR。
- 粒子与碎片数量。
- 折射缓冲区分辨率。
- 残影采样次数。
- 非关键噪声层数量。

系统基于设备能力选择初始档位，并根据一段连续帧耗时进行降级。质量变化不得发生在命中定格的中间帧，避免视觉跳变。

## 8. 声音设计

- 默认状态始终为关闭。
- 用户第一次开启时才加载音频文件并创建音频图。
- 音频分为低频环境、拔刀、命中和破晓四类，允许统一静音。
- 浏览器拒绝播放、文件加载失败或音频上下文暂停时，界面保持静音状态，不显示阻塞错误。
- 主题切换后不自动继承播放中的声音；目标主题仍按自己的默认静音规则启动。
- 不使用参考作品的音乐、对白或音效采样。

## 9. 可访问性与安全

- 正文使用语义化 DOM，普通文字对比度至少 4.5:1，大字号至少 3:1。
- 所有链接、声音开关、主题切换和章节入口均可使用键盘操作，并有可见焦点。
- 屏幕阅读器按内容顺序读取，不朗读装饰性战术坐标和 WebGL 图形。
- `prefers-reduced-motion` 下取消震屏、视差、高速拖影和连续粒子，用不超过 200 毫秒的裁切或淡入表达状态变化。
- 高亮闪烁不得达到每秒 3 次；命中白光限制在局部区域和短持续时间，正文区域不得闪烁。
- 页面不可依赖颜色单独表达当前章节或交互状态。
- WebGL 不可用时提供 CSS 刀光和静态战术线，内容与主题切换保持完整。

## 10. 故障处理

| 故障 | 行为 |
| --- | --- |
| WebGL 初始化失败或上下文丢失 | 切换到 CSS 表现层，保留 DOM 内容与交互 |
| 动画执行中快速滚动 | 取消过期编排，由目标章节状态接管 |
| 音频加载或播放失败 | 保持静音，不阻塞页面 |
| 无效内容 ID | 清理片段并回到目标主题顶部 |
| 单条内容字段异常 | 跳过损坏节点并记录开发期错误，其他内容继续显示 |
| 页面隐藏 | 暂停持续渲染与环境音；恢复时根据当前状态重绘 |
| 主题切换 | 先完成当前页面卸载，再由目标 URL 创建新运行时 |

## 11. 性能预算

- 活跃战斗阶段以接近 60 FPS 为目标；持续超出帧预算时自动降低画质。
- 阅读状态不维持高频动画循环；只在必要的输入、尺寸变化或低频环境更新时重绘。
- 同一时刻只存在一个主题的 WebGLRenderer 和音频图。
- 音频与非首屏资源延迟加载，不阻塞姓名、主题切换和首屏 DOM。
- 连续完成 20 次双向主题切换后，不应出现持续增长的 WebGL 上下文、事件监听器、音频节点或纹理资源。

## 12. 测试与验收

### 12.1 单元测试

- 共享内容校验与稳定 ID 唯一性。
- 内容到战线章节的映射。
- `idle → armed → impact → reading → leaving` 状态转换。
- 快速反向滚动时的动画取消。
- 两个主题之间的 URL 片段转换与无效 ID 回退。
- 自适应质量档位只改变允许的渲染参数。

### 12.2 集成与端到端测试

- 正常访问 `/nightfall/` 播放完整开场；未输入时稳定停在 `armed` 状态。
- 首个输入在 10 秒内完成破幕并显示真实内容。
- 滚动可访问全部内容，不需要主动出招。
- 点击、拖拽和触摸只增加表现反馈，不改变内容状态。
- 声音保持默认关闭，用户开启后正常加载，再关闭后立即静音。
- 从任一记忆切换主题后定位同一稳定内容 ID。
- 从带片段 URL 进入时跳过完整开场并正确聚焦章节。
- WebGL 失败、减少动态效果和音频失败路径仍可完整浏览。

### 12.3 视觉、性能与无障碍测试

- 桌面和移动端视觉回归：构图、色谱、招式时序和章节顺序一致。
- 中端真实手机测试：活跃战斗阶段能通过自动质量策略维持流畅交互。
- 键盘、屏幕阅读器、焦点顺序、对比度和闪光频率检查。
- 主题反复切换与页面重复进入的 GPU、音频、事件和内存泄漏检查。

### 12.4 验收条件

设计实现只有同时满足以下条件才可验收：

1. 页面在 2.8 秒内完成锁定；首次输入后的 7.2 秒内完成四镜头签名开场并展示真实个人内容。
2. `/` 与 `/nightfall/` 视觉和运行时互不依赖。
3. 两个主题读取同一份个人内容，并能按稳定 ID 双向切换到相同章节。
4. 桌面与移动端保持相同战斗编排，低质量档不删减内容或章节。
5. 无 WebGL、无音频、减少动态效果和纯键盘路径均可完成全部浏览。
6. 正文阅读时强动效停止，内容对比度和可访问性达标。

## 13. 实施范围边界

本规格可作为单一实施计划处理，范围包括共享内容 ID、双主题导航契约、新主题入口、独立战斗渲染器、DOM 内容、手势、可选音频、降级策略与测试。它不包括替换现有深海视觉、改写个人故事、制作第三套主题或引入后端服务。
